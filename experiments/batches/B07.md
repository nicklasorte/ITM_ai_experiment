# Batch B07: terminal clutter at concealed sites, and one source per loss

Planner: Claude Opus 5.5, 2026-11-21. Worker: the session model.
Predictions were committed before any scored run of these settings.

## Purpose

The B06 reviewers agreed (3 of 3) that ITM's A_fo was standing in for a
site-specific loss near the terminals that rises with frequency, and that
the delta forms stack empirical terrain allowances fitted without each
other. Nick allowed the Phase 2 `siting` column as an input for a terminal
clutter term. This batch adds ITU-R P.2108 section 3.1 at concealed sites,
tests whether its frequency and height shape matter (constant-offset
control), and removes the empirical corrections that the clutter term
would double count.

## What the siting codes mean

From the Phase 2 readme (`data/raw/its_phase2.zip`, `phase_2.txt`): many
paths come in pairs, one "open" and one "concealed". A path is open (`O`)
if its mobile terminal "has a clear, unobstructed foreground in the
direction of the other terminal"; on a concealed path (`C`) "the terminal
is immediately behind a grove of trees or a building". `A` appears only in
R1 (416 measured rows) and the readme doesn't define it.

The mobile terminal is the transmitter in R1, R2, and R3 (the receiver
coordinates are fixed in `r1path.txt` to `r3path.txt`) and the receiver in
VA (seven fixed transmitter sites in `vapath.txt`).

Mapping (design choices, no new constants):

| Code | P.2108 clutter type | Why |
| --- | --- | --- |
| `C` | trees/forest (R = 15 m, eq. (2a)) | "a grove of trees or a building"; trees and urban share R and the equation in Table 3 |
| `O` | none (0 dB) | a clear foreground; eq. (2b) for open/rural would add height-gain loss that ITM's ground reflection already carries |
| `A` | none (0 dB) | undefined in the readme |

### `p2108_height_gain_rev1.m`: ITU-R P.2108-1 section 3.1

Height gain terminal correction model, ITU-R P.2108-1 (09/2021):
A_h = 0 for h ≥ R; otherwise eq. (2a) A_h = J(ν) − 6.03 with
ν = K_ν √(h_dif θ_clut) (eq. (2c)–(2e), (2g)), or eq. (2b) for water/sea
and open/rural. R from Table 3; street width w_s = 27 m (Table 2 default).

- The equations were read from the Recommendation. The PDF text extraction
  dropped the square root in eq. (2c); the NTIA/ITS reference
  implementation (github.com/NTIA/p2108,
  `src/HeightGainTerminalCorrectionModel.cpp`) has it.
- The code reproduces all 16 NTIA/ITS published test vectors with the
  Table 3 heights and the default street width
  (github.com/NTIA/p2108-test-data) to the published 0.1 dB.
  *Correction (B07 reviewer pass, 2026-11-21): the test-data file has 18
  valid rows, not 16, and the unit test checks 6 of them (all at 1.5 GHz,
  2 m). Three reviewers' Python ports of the same equations match all 18
  to within 0.05 dB; the MATLAB test of all 18 was added in B08.*
- **Frequency range.** Section 3.1 covers 0.03–3 GHz. 29 % of the Phase 2
  rows are at 4.6–9.2 GHz. Rule `"extend"` (used in every run) applies
  eq. (2a) above 3 GHz: it is a single knife edge over the clutter, which
  has no frequency limit of its own, and 3 GHz is the range over which the
  section was validated. **This is a design choice the reviewers should
  check.** Rule `"recommendation"` errors outside the range; below 0.03 GHz
  both rules error. No Phase 2 row is below 0.03 GHz.
- Loss falls as the terminal rises (tested), the measured sign.

Size on the 2,272 concealed rows: mean 16.75 dB. By band: R1 and R2
(transmitter at 6.6–7.3 m) 14.1, 17.9, 21.0, 26.5 dB for <0.5, 0.5–1.5,
1.5–3, >3 GHz; VA (receiver at 2 m or 11.7–15 m) 8.2, 14.8, 18.7, 22.7 dB
(0 dB at 15 m).

### Row metadata: needs an evaluator change (PR #3, not made)

**Open and concealed twins share one terrain profile: 71 of the 108
concealed paths.** The evaluator passes the variant the profile, heights,
frequency, and climate, but not the link, so the variant can't tell a
concealed row from its open twin. A lookup keyed by the profile was built
first and failed on exactly these collisions. It was removed.

The variant now reads `cfg.row` (fields `set`, `siting`, `reversed`), and
errors if a clutter setting runs without it, so no row silently gets 0.
The evaluator change that would supply `cfg.row` touches
`eval/run_eval_rev1.m` (`run_rows`) and `eval/physics_battery_rev1.m`
(the real-link reciprocity pair, with `reversed = true` on the swapped
call). Nick approved it on 2026-11-21; it is PR #3 (branch
`eval-row-metadata-rev1`, stacked on PR #2), checked on the Mac from a
scratch copy (parity 6.8 × 10⁻¹³ dB; battery with clutter passes). Until
it is merged, only experiment 705 can run.

### Stacking: one source per loss

- `"deygout_isolated"`: the isolation-weighted edges of B06 summed as in
  Deygout (1966), J_p + w_t J_t + w_r J_r, without P.526-11's empirical
  correction C = 10 + 0.04 D and factor T (eq. (50a)–(52)).
- `"bullington_uc"`: Bullington without the eq. (57) correction.
- Delta forms `"delta_deygout_isolated"` and `"delta_bullington_uc"`.

### Multi-edge overshoot

604's measured 3 and 4+ edge rows on R2 are 11.5 and 7.5 dB high. On those
paths T is near 1, so C adds 10–14 dB: the overshoot is about the size of
C. Removing C (702, 705) is the fix proposed here. The P.526-16 section 4.4
C_N and sub-path terms and the section 4.2 rounded-obstacle term weren't
read reliably in this session and aren't built.
