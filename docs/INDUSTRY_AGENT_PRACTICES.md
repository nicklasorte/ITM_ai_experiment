# How industry runs AI agents on systems that can check themselves

Rev 1, 2026-11-21. A review of how companies deploy AI agents where an
automatic check says whether a change is better or worse: CI/CD pipelines,
tests, code migrations, production optimization, chip design, and telecom
networks. It ends with the practices this repository adopted. The
academic side is in
[AGENT_OPTIMIZATION_LITERATURE.md](AGENT_OPTIMIZATION_LITERATURE.md).

## The common pattern

Across every deployment below, the agent proposes and a deterministic check
disposes. Industry deploys agents first where the check is cheap and
trustworthy (a build, a test suite, a scheduler metric) and keeps a human
on the last step wherever the check can't see everything.

## 1. Software: tests, migrations, and self-healing CI

### Assured test improvement (Meta)

Meta's TestGen-LLM extends existing human-written test classes, and its
filters guarantee that a candidate measurably improves the original suite,
which removes hallucination as a risk
([Alshahwan et al., FSE 2024](https://arxiv.org/pdf/2402.09171.pdf)). Of its
generated tests on Instagram Reels and Stories, 75 % built, 57 % passed
reliably, and 25 % increased coverage; across Instagram and Facebook
test-a-thons it improved 11.5 % of the classes it was applied to, and
engineers accepted 73 % of its recommendations
([arXiv abstract](https://arxiv.org/abs/2402.09171)). It submits for human
review only tests it can guarantee are improvements
([paper](https://arxiv.org/pdf/2402.09171)).

**Lesson:** generate many candidates, discard everything that doesn't
measurably improve, and show humans only the survivors. Meta calls this
"Assured LLM-based software engineering."

### Large-scale code migrations (Google)

- A case study of 39 migrations reported an estimated 50 % cut in total
  migration time compared with earlier manual migrations
  ([Ziftci et al. 2025](https://arxiv.org/pdf/2504.09691v1)), and 69.46 % of
  the edits were generated by the LLM
  ([arXiv HTML](https://arxiv.org/html/2504.09691v1)).
- Google used multi-agent systems to migrate some of its largest production
  models from TensorFlow to JAX, reporting a 6x faster migration
  ([Google Cloud, May 2026](https://cloud.google.com/blog/topics/developers-practitioners/6x-faster-migration-from-tensorflow-to-jax)).
  The system pairs static analysis with an orchestrator and coder agents
  that follow AI-written migration plans
  ([arXiv 2603.27296](https://arxiv.org/pdf/2603.27296)).

**Lesson:** decompose the work, let static analysis and tests define
"done," and keep an orchestrator in charge of a plan.

### Self-healing CI pipelines

- **Elastic** added an AI agent to its build pipelines so dependency-update
  pull requests that break the build fix themselves: the agent commits a fix
  to the PR branch and the pipeline restarts
  ([Elastic Search Labs](https://www.elastic.co/search-labs/blog/ci-pipelines-claude-ai-agent)).
  Automated update PRs had bumped 41 % of their dependencies in about six
  months
  ([same](https://www.elastic.co/search-labs/jp/blog/ci-pipelines-claude-ai-agent)).
  One practical lesson: long verification builds kept getting canceled by
  newer changes on main, interrupting the agent
  ([same](https://www.elastic.co/search-labs/pt/blog/ci-pipelines-claude-ai-agent)).
- **Semaphore** documents the same loop: when CI fails, a separate pipeline
  starts an agent that reads the job logs, pushes a fix to a separate branch,
  reruns CI, and opens a PR only if it passes
  ([Semaphore docs PR](https://github.com/semaphoreio/semaphore/pull/716/files)).
- **Nx** retries flaky tasks automatically and uses an agent to propose fixes
  for genuine failures
  ([Nx blog](https://nx.dev/blog/nx-self-healing-ci)).

**Lesson:** the agent never merges on its own judgment; it merges because the
same pipeline that gates human changes passed.

### AI code review at scale (Uber)

Uber's uReview analyzes over 90 % of the roughly 65,000 diffs landed each
week; engineers mark 75 % of its comments useful
([Uber engineering](https://www.uber.com/ae/ar/blog/ureview/)). It splits
review into generation, filtering, validation, and deduplication stages
([same](https://www.uber.com/cz/ru/blog/ureview/)), and because the LLM is
stochastic it runs each review five times to virtually eliminate missed
detections ([same](https://www.uber.com/hk/en/blog/ureview/)). The main
challenge it names is false positives
([same](https://www.uber.com/en-GB/blog/ureview/)).

**Lesson:** treat a single agent run as a noisy sample; repeat and
deduplicate, and measure usefulness from developer feedback.

### The industry-wide caution (DORA 2025)

Google's 2025 DORA survey of nearly 5,000 professionals found AI adoption
now improves software delivery throughput but still increases delivery
instability
([DORA 2025 report](https://services.google.com/fh/files/misc/2025_state_of_ai_assisted_software_development.pdf)).
Adoption reached 90 %, while 30 % of respondents trust AI output a little or
not at all ([Google blog](https://blog.google/technology/developers/dora-report-2025/?lid=GrrqvSt4tBeputib)).

**Lesson:** speed is easy; stability has to be measured and defended.

## 2. Production optimization: AlphaEvolve at Google

AlphaEvolve's scheduling heuristic for Borg, in production for over a year,
continuously recovers an average of 0.7 % of Google's worldwide compute
([DeepMind](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)).
DeepMind stresses the operational advantages of its output being
human-readable code: interpretability, debuggability, predictability, and
ease of deployment
([DeepMind](https://deepmind.google/en/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)).
An industry analysis distills it: production agents need deterministic
scorekeepers ([VentureBeat](https://venturebeat.com/infrastructure/googles-alphaevolve-the-ai-agent-that-reclaimed-0-7-of-googles-compute-and-how-to-copy-it)).
AlphaEvolve became generally available on Google Cloud in July 2026
([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/alphaevolve-on-google-cloud?e=0)).

**Lesson:** the closest industrial analog to this project. A legacy
heuristic, an agent proposing readable code changes, and an evaluator that
runs against real workloads.

## 3. Chip design (EDA)

- Synopsys's design-space optimizer DSO.ai has passed 100 production
  tape-outs, while its newer autonomous agents are still in customer
  engagements
  ([Tom's Hardware](https://tomshardware.com/tech-industry/semiconductors/synopsys-debuts-autopilot-platform-for-developing-chips-autonomously-using-ai-new-agentengineer-platform-is-poised-for-general-availability-by-the-end-of-2026)).
- Cadence frames a ladder from optimization AI through agentic workflows to
  full autonomy, and Siemens ships separate RTL, lint, clock-domain,
  verification-planning, and debug agents
  ([Tom's Hardware](https://www.tomshardware.com/tech-industry/semiconductors/the-state-of-agentic-ai-in-chip-design-tools-in-2026-cadence-synopsys-and-siemens-all-pitch-autonomous-engineers)).
- Siemens announced self-verifying agentic workflows in 2026
  ([Futurum](https://futurumgroup.com/insights/synopsys-cadence-and-siemens-take-agentic-chip-design-autonomous-at-dac/)).

**Lesson:** the optimizer that tunes parameters inside a verified flow
reached production years before the free-roaming agents did. That matches
this project's order: recalibration (DSO-like) is the baseline; structural
agents have to beat it.

## 4. Telecom: closed-loop network agents

- Ericsson positions agentic AI for assurance, incident resolution,
  provisioning, and network optimization, moving operations toward
  proactive, closed-loop management
  ([Ericsson white paper, July 2026](https://www.ericsson.com/en/reports-and-papers/white-papers/adapting-agentic-ai)).
- Verizon reports applying agentic AI across its 60,000-site vRAN to planned
  configuration changes, service assurance, and optimization, and has called
  for industry-wide interoperability standards for agentic systems
  ([IEEE ComSoc Technology Blog](https://techblog.comsoc.org/?p=1076611)).
- Nokia released an Autonomous Networks Agent Library in June 2026
  ([Nokia](https://www.nokia.com/newsroom/nokia-advances-autonomous-networks-portfolio-with-upgraded-agentic-ai-capabilities-dtw26-a/)).
- No standardized protocol yet exists for agentic command, control, and
  assurance across multi-vendor networks
  ([IEEE ComSoc Technology Blog](https://techblog.comsoc.org/2026/06/22/ai-ran-and-agentic-ai-get-real-ericsson-nokia-verizon-other-network-operators-enter-into-a-new-automation-era/)).

**Lesson:** in RF operations, agents act inside closed loops with intent,
measured outcomes, and human oversight. Agents that change the propagation
*models* those networks are planned with are not part of these offerings.

## What this repository adopted

| Practice | Who does it | Adopted here (2026-11-21) |
| --- | --- | --- |
| Assured improvement: show humans only candidates that measurably beat the incumbent | Meta TestGen-LLM | Acceptance rule (FRAMEWORK.md) |
| Deterministic scorekeeper the agent can't edit | AlphaEvolve | `eval/` read-only, enforced by the `guard` CI workflow and `Agent-Role` commit trailers |
| Readable output over black-box gains | AlphaEvolve | Named, cited submodel swaps only |
| Gate every change with the same pipeline humans use | Elastic, Semaphore | `guard` runs on every push and pull request: agent scope, frozen-data hashes, `results.tsv` format, restricted names (from a repository secret) |
| Repeat stochastic agent steps and deduplicate | Uber uReview | Three independent reviewer sessions; act on findings two of three report |
| Track stability, not just speed | DORA | `results/batch_stability.tsv`, one row per batch; a rising revert or gate-failure rate triggers a review |
| Retry flaky steps separately from real failures | Nx | Infrastructure failures retried once and logged as `infra`, never counted as results |
| Don't let long verification runs get canceled by newer commits | Elastic | One evaluation at a time per branch |
| Shadow before production | Telecom closed loops | `experiments/shadow/<study>/` paired comparison, read by Nick before any outside use |
| Parameter optimizer first, free agent second | EDA (DSO.ai before agents) | Every kept change reported against the recalibrated baseline R01 |

### Evidence from this repository: why the gates matter

The first recalibrated-ITM run (experiment R01, interim data) shows the risk
that every system above guards against. A conventional optimizer fitting six
ITM constants cut the composite score from 13.9 dB to 12.1 dB and the
Colorado mountain error from 28.6 dB to 19.1 dB. But it did so partly by
predicting less loss than the measured lower bound on 56 % of no-signal
results (baseline 28 %), and its fitted constants put a 19 dB jump into the
single-ridge distance sweep (baseline 8 dB). Both gates reject it. An agent
optimizing the same score would find the same shortcut unless the gates are
part of the score it sees.
